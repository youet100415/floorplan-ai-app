# 유닛 에디터 및 유닛 배치 UX/작업 플로우 제안서

## 1. 결론

유닛 제작과 유닛 배치는 다음 두 위치로 분리하는 것이 적절합니다.

- **유닛 에디터 워크스페이스**: 재사용 가능한 유닛 모듈을 만들고 저장하는 곳
- **평면 완성 워크스페이스**: 프로젝트의 조닝 결과에 저장된 유닛을 배치하고 검토하는 곳

사용자의 기본 흐름은 다음과 같습니다.

```text
[유닛 에디터]
   유닛 제작 → 검증 → 라이브러리 저장
                       ↓
[평면 완성]
   조닝 설정 → 평면 생성 → 유닛 배치 → 조닝 영역에 적용 → 검토/확정
```

초기 개발에서는 **기존 유닛 템플릿을 불러와 조닝 영역에 배치하는 방식**을 기본 흐름으로 삼는 것을 권장합니다. 조닝 화면 안에서 유닛을 처음부터 작도하는 기능은 보조 기능 또는 후속 단계로 두는 편이 사용자의 작업 목적과 구현 난이도에 모두 적합합니다.

---

## 2. 현재 앱 기준의 화면 구조

현재 로컬 앱에는 상단에 다음 두 워크스페이스가 있습니다.

### A. 유닛 에디터

재사용 가능한 침실, 욕실, 주방 등의 모듈을 단독 캔버스에서 제작하고 저장합니다.

주요 기능:

- 새 외곽 만들기
- 벽, 실/존, 문/창, 팬 등 작도 도구
- 유닛 이름과 타입 힌트 입력
- 라이브러리 저장
- 저장된 유닛 목록 확인

### B. 평면 완성

프로젝트의 전체 평면을 만들고, 조닝과 유닛 배치를 진행합니다.

현재 단계:

1. **조닝**: 건물 외곽, 복도 동선, 코어/피난 영역 설정
2. **유닛 배치**: 조닝 결과에 라이브러리 유닛 적용

현재는 평면 생성을 완료해야 유닛 배치 단계가 활성화됩니다. 따라서 유닛 배치를 조닝과 동시에 수행하는 구조가 아니라, **조닝 결과가 만들어진 후 배치하는 순차형 흐름**으로 보는 것이 맞습니다.

## 3. 사용자 작업 플로우

### 3.1 유닛을 새로 제작하는 경우

```text
유닛 에디터 진입
 → 작도 캔버스 크기 지정
 → 외곽 생성
 → 내부 존/벽 작도
 → 문·창·가구 배치
 → 유닛 정보와 타입 힌트 입력
 → 유효성 검사
 → 라이브러리 저장
```

저장 전에는 최소한 다음 항목을 검사해야 합니다.

- 외곽선이 닫힌 도형인지
- 벽이 자기 자신 또는 다른 벽과 비정상적으로 교차하지 않는지
- 문과 창이 실제 벽에 연결되어 있는지
- 문 폭이 벽 길이를 초과하지 않는지
- 존의 면적이 0이 아니며 중복되지 않는지
- 가구가 벽이나 다른 고정 객체와 충돌하지 않는지
- 기준점(anchor point)과 단위가 정의되어 있는지

검사에 실패하면 저장을 막기보다, 가능하면 오류 위치를 캔버스에 표시하고 사용자가 수정할 수 있게 해야 합니다. 단, 엔진 입력으로 사용할 수 없는 상태에서는 `배치 가능` 상태로 저장해서는 안 됩니다.

### 3.2 저장된 유닛을 프로젝트에 배치하는 경우

```text
평면 완성 진입
 → 조닝 조건 설정
 → 평면 생성
 → 유닛 배치 단계 활성화
 → 조닝 영역 선택
 → 라이브러리에서 유닛 선택
 → 후보 미리보기
 → 위치·회전·좌우 반전·크기 조정
 → 배치 적용
 → 충돌/면적/접속성 검토
 → 확정 또는 되돌리기
```

여기서 중요한 점은 **라이브러리 유닛과 프로젝트에 배치된 유닛을 서로 다른 객체로 취급하는 것**입니다.

- 라이브러리 유닛: 재사용 가능한 원본 템플릿
- 배치 유닛: 특정 프로젝트의 특정 조닝 영역에 적용된 인스턴스

프로젝트에서 배치 유닛을 수정할 때 원본 라이브러리까지 바뀌면 안 됩니다. 따라서 기본 동작은 `프로젝트용 복제본 편집`으로 하고, 원본을 수정하려면 별도의 `라이브러리 업데이트` 동작을 제공해야 합니다.

## 4. 유닛 배치 화면에서 보여야 할 정보

유닛 배치 화면은 조닝 결과와 라이브러리를 한 화면에서 비교할 수 있어야 합니다.

### 왼쪽 패널: 유닛 라이브러리

- 유닛 미리보기 썸네일
- 유닛 이름
- 유닛 타입: 침실, 욕실, 주방 등
- 외곽 크기와 면적
- 포함 객체: 침대, 욕실 설비 등
- 적용 가능한 조닝 타입
- 버전 또는 수정일
- 검색 및 필터

### 중앙 캔버스: 프로젝트 평면

- 전체 외곽선
- 조닝 영역
- 복도 및 코어
- 이미 배치된 유닛
- 선택된 조닝 영역의 강조 표시
- 배치 후보의 반투명 미리보기
- 충돌, 초과 면적, 접속 불가 등의 오류 표시

### 오른쪽 패널: 선택 항목 속성

조닝 영역을 선택했을 때:

- 영역 용도
- 요구 면적
- 현재 면적
- 허용 오차
- 필요한 접속점 또는 복도 접속 조건
- 추천 유닛 목록

배치 유닛을 선택했을 때:

- 원본 라이브러리 유닛
- 프로젝트 내 인스턴스 ID
- 위치와 회전
- 좌우 반전 여부
- 외곽 크기
- 배치 상태
- 충돌 및 검증 결과

## 5. 유닛 매칭과 배치 규칙

유닛 후보는 이름만으로 매칭하지 않고 조닝 영역의 조건과 비교해야 합니다.

```text
조닝 영역 조건
  - 용도
  - 요구 면적
  - 최소 폭/깊이
  - 접속 방향
  - 창면 또는 외곽 접촉 조건
        ↓
유닛 라이브러리 메타데이터 비교
        ↓
추천 후보 목록
        ↓
사용자 선택 및 배치
```

초기 버전의 추천 점수는 단순하고 설명 가능하게 두는 것이 좋습니다.

- 용도 일치: 40%
- 면적 적합성: 30%
- 폭/깊이 적합성: 15%
- 접속 방향 적합성: 10%
- 창면/외곽 조건: 5%

AI라는 표현은 신중하게 사용해야 합니다. 현재의 `ai_metadata`는 모델 학습 데이터라기보다 **검색·추천·분류를 위한 메타데이터**에 가깝습니다. 실제 학습 파이프라인이 별도로 구축되기 전에는 화면 문구를 `AI 학습 정보`보다 `유닛 분류 및 추천 정보`로 표현하는 것이 정확합니다.

## 6. 데이터 처리 시점

데이터 처리는 다음 세 시점으로 나누는 것이 좋습니다.

### 6.1 유닛 저장 시

사용자가 유닛 에디터에서 저장하면 다음 데이터가 생성됩니다.

- 외곽 및 벽 geometry
- 문·창 등 opening 정보
- 내부 존 정보
- 가구 및 객체 정보
- 기준점과 단위
- 추천/검색용 메타데이터
- 유효성 검사 결과

이 단계에서는 보르노이 연산을 실행할 필요가 없습니다. 라이브러리에 재사용 가능한 원본을 저장하는 단계이기 때문입니다.

### 6.2 조닝 결과 생성 시

조닝 결과가 확정되면 각 영역에 다음 조건이 부여됩니다.

- zone ID
- 용도
- 요구 면적
- 최소 치수
- 외곽 접촉 조건
- 복도 또는 다른 영역과의 접속 조건

이 단계에서는 라이브러리 후보를 검색하고 추천할 수 있습니다. 아직 최종 벽체를 확정하지는 않습니다.

### 6.3 유닛 배치 적용 시

사용자가 유닛을 선택하고 `적용`을 누르면 다음 순서로 처리합니다.

1. 유닛 인스턴스 생성
2. 기준점에 따라 위치 정렬
3. 회전/반전/스케일 적용
4. 조닝 영역과의 포함 관계 검사
5. 기존 유닛 및 복도와의 충돌 검사
6. 문·접속점과 복도 연결 검사
7. 통과하면 프로젝트 평면에 반영
8. 실패하면 미리보기 상태로 유지하고 오류 안내

보르노이 또는 Power Diagram은 이 단계 이후에 선택적으로 실행하는 **자동 내부 분할 또는 대안 생성 엔진**으로 두는 것이 좋습니다. 유닛 배치 자체와 보르노이 계산을 하나의 버튼에 묶으면 실패 원인을 사용자가 이해하기 어렵습니다.

## 7. 보르노이/Power Diagram의 역할 재정의

현재 문서처럼 “유닛의 노드와 엣지를 읽어 벽과 문을 자동 완성한다”고 단정하면 구현 범위가 지나치게 커지고, 일반적인 유닛 템플릿 배치와도 역할이 섞입니다.

다음처럼 단계적으로 정의하는 것이 더 현실적입니다.

### 1단계: 템플릿 배치

저장된 벽, 문, 존 geometry를 그대로 프로젝트에 배치합니다.

### 2단계: 배치 보정

- 조닝 영역 안으로 이동
- 외곽선과 정렬
- 복도 접속점에 문 정렬
- 100mm 또는 300mm 모듈로 스냅
- 충돌이 없는 위치 탐색

### 3단계: 자동 생성 또는 대안 생성

여러 공간 노드와 면적 조건을 입력으로 받아 Power Diagram을 계산하고, 결과를 직교화하여 후보 평면을 생성합니다.

이 결과는 바로 확정하지 않고 `자동 생성안` 또는 `대안`으로 보여줘야 합니다. 사용자가 기존 배치와 비교하고 승인한 뒤 프로젝트에 반영하도록 해야 합니다.

## 8. 데이터 모델에서 보완할 항목

현재 JSON 스키마의 방향은 좋지만, 실제 프로젝트 배치까지 지원하려면 다음 필드가 추가되어야 합니다.

- `schema_version`: 스키마 버전
- `coordinate_system`: 좌표계와 원점 설명
- `unit`: mm 또는 m 등 측정 단위
- `status`: draft, valid, published, archived
- `library_version`: 라이브러리 원본 버전
- `placement_constraints`: 배치 가능 조건
- `connection_points`: 복도/입구/설비 연결점
- `validation`: 오류, 경고, 검증 시각
- `project_instance`: 프로젝트에 배치된 경우의 위치/회전/반전 정보
- `source_unit_id`: 배치 인스턴스가 참조한 원본 유닛 ID

특히 `center_point`와 `anchor_point`만으로는 배치가 불안정합니다. 문이나 복도 연결을 자동화하려면 어떤 벽에 어떤 접속점이 있는지 명시적인 `connection_points`가 필요합니다.

예시는 다음과 같습니다.

```json
{
  "schema_version": "1.1.0",
  "unit": "mm",
  "unit_metadata": {
    "unit_id": "unit_bed_84a_01",
    "unit_name": "84A 침실 Type 01",
    "status": "published",
    "bounding_box": { "width": 4800, "height": 3600 },
    "anchor_point": { "type": "bottom_left", "x": 0, "y": 0 }
  },
  "placement_constraints": {
    "zone_categories": ["bedroom"],
    "min_zone_area_sqm": 15.0,
    "requires_exterior_contact": true
  },
  "connection_points": [
    {
      "connection_id": "entry_01",
      "type": "door",
      "wall_id": "w_04",
      "offset": 1200,
      "direction": "inward"
    }
  ],
  "validation": {
    "is_valid": true,
    "errors": [],
    "warnings": []
  }
}
```

## 9. MVP 개발 순서

### Phase 1: 독립 유닛 에디터

- 외곽과 벽 작도
- 존 생성
- 문/창 배치
- 기본 유효성 검사
- 이름과 타입 저장
- 라이브러리 목록 표시

### Phase 2: 조닝과 수동 배치 연결

- 조닝 후 유닛 배치 단계 활성화
- 라이브러리 목록 표시
- 조닝 영역 선택
- 드래그 앤 드롭 또는 `배치` 버튼
- 위치/회전/반전
- 충돌 및 영역 포함 검사
- 적용 취소와 되돌리기

### Phase 3: 조건 기반 추천

- 면적과 용도 기반 후보 필터
- 추천 점수와 추천 이유 표시
- 부적합 사유 표시

### Phase 4: 자동 보정 및 생성 엔진

- 접속점 자동 정렬
- 모듈 그리드 보정
- Power Diagram 대안 생성
- 직교화
- 대안 비교 및 승인

## 10. 문서에서 수정해야 할 표현

다음 표현은 현재 구조와 구현 범위를 고려해 바꾸는 것이 좋습니다.

| 기존 표현 | 권장 표현 |
|---|---|
| 글로벌 유닛 라이브러리 | 유닛 에디터 워크스페이스의 라이브러리 |
| 메인 프로젝트 3단계 탭 | 평면 완성 워크스페이스의 조닝 → 유닛 배치 단계 |
| 조닝된 공간에 유닛을 직접 새로 작도 | 라이브러리 유닛을 먼저 배치하고 필요 시 프로젝트용 복제본을 편집 |
| AI 학습 메타데이터 | 유닛 분류 및 추천 메타데이터 |
| 적용 즉시 보르노이로 최종 벽체 확정 | 배치 검증 후 필요할 때 자동 생성/보정 대안 실행 |
| 저장하면 DB에 저장 | 현재는 저장소 구현에 따라 브라우저 저장 또는 서버 DB 저장 |
| 문 위치를 보르노이 교차점으로 자동 결정 | 템플릿 문 위치를 우선 사용하고, 자동 생성 모드에서만 계산 |

## 11. 개발팀에 전달할 최종 질문

초기 구현 방향은 다음과 같이 합의하는 것이 좋습니다.

> 초기 MVP에서는 유닛 에디터에서 미리 제작한 템플릿을 라이브러리에 저장하고, 평면 완성의 조닝 결과에 해당 템플릿을 선택·배치하는 흐름을 기본으로 한다. 조닝 화면에서 유닛을 처음부터 새로 작도하는 기능은 MVP 범위에서 제외하거나, 배치된 유닛의 복제본을 편집하는 보조 기능으로 제공한다. 보르노이/Power Diagram은 템플릿 배치의 필수 과정이 아니라, 후속 자동 보정 및 대안 생성 엔진으로 연동한다.

이 방향이면 사용자는 “어디에서 만들고, 어디에서 사용하는지”를 쉽게 이해할 수 있고, 개발팀도 유닛 저장·유닛 배치·자동 생성 엔진을 단계별로 검증할 수 있습니다.
